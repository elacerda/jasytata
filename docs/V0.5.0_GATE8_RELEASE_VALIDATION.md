## Gate 8 production-preview blocker follow-up

The initial Gate 8 candidate review missed a production-preview blocker. `vite build` emitted `/jasytata/assets/...` URLs, but Vite preview was using `/` because both the development server and preview report `command === "serve"`. The missing assets then received the SPA `index.html` fallback as `200 text/html`, leaving the production-preview page blank.

The Vite base now uses `/` for development and `/jasytata/` for both build and preview by checking `isPreview` alongside the build command. This keeps the GitHub Pages deployment base unchanged. A focused Vite config regression test covers development, build, and preview resolution. The production build now starts a real local `vite preview`, checks `/jasytata/`, requests every emitted JS/CSS URL, verifies its content type, rejects HTML fallback content, and compares the response bytes with the emitted file.

Follow-up validation passed: `make test` reports **900 tests passed in 57 files**; `make lint`, `make typecheck`, `make build`, and `git diff --check` pass. The build smoke starts a production preview and confirms the emitted JavaScript and CSS both return HTTP 200 with their expected content types and exact emitted-file bytes. The requested manual check returned `200 text/javascript` for the built JavaScript URL; its first bytes were `var Gw=...`, not HTML. `/jasytata/` returned `200 text/html` and rendered the Jasytata title and app root in headless Chrome. The development server also rendered Jasytata at `/`.

This local follow-up closes the production-preview blocker. The separate full Gate 8 browser checklist remains pending, so it does not authorize release or deployment.

### Fixed-viewport sizing and wheel behavior

Before changing CSS, Chrome reported `innerHeight=757`, `documentElement.clientHeight=757`, `documentElement.scrollHeight=1892`, and `body.scrollHeight=757`. `.app-shell`, `.workspace`, map column, and panels already fit their viewport sizes. The overflow came from the absolutely positioned, visually hidden `RA and DEC pairs` label in `.import-section`: that section was not positioned, so the label used the document as its containing block and extended to approximately 1892 px. Adding `position: relative` to `.import-section` keeps the label inside the independently scrolling left panel. This fixes the actual containing-block error without changing the app-shell, workspace, map, or Aladin sizing model.

After the fix, Chrome reported `innerHeight=900`, document client height 900, document scroll height 900, and body scroll height 900 at both desktop widths. `.app-shell` was exactly 900 px high. The left panel scrolled independently (its `scrollTop` changed while the right panel remained at zero); wheel input over the right panel then changed only its `scrollTop`. `window.scrollY` remained zero throughout.

Plain wheel over the map does not zoom Aladin. The capture policy stops the event from reaching Aladin and does not cancel it; the fixed viewport has no intended document scroll behavior. Ctrl-wheel changed Aladin FOV from 6.046° × 4.968° to 4.757° × 3.909°. Meta-wheel then changed it to 3.742° × 3.075°. Dragging visibly panned the map while preserving its zoom.

**Status: frozen contract.** This document closes Gate 2. It authorizes the later
implementation gates described below; it does not authorize runtime changes in

### 4.1 Small Schema v3 profile shape

The following are contract examples, not implementation permission for Gate 2:

```ts
type FootprintRole = "observed_area" | "nominal_envelope" | "target_access";
type GeometryFidelity = "exact" | "approximate";
type PositionAngleMode = "fixed" | "user_selected" | "per_pointing" | "not_applicable";

interface FootprintSemantics {
  role: FootprintRole;
  fidelity: GeometryFidelity;
  approximation_notice?: string;
}
interface ProfileProvenance {
  references: { url: string; title?: string; locator?: string }[];
  parameter_sources: { parameter_path: string; reference_url: string; note?: string }[];
  assumptions: string[];
  limitations: string[];
}
interface PositionAnglePolicy {
  mode: PositionAngleMode;
  required: boolean;
}
interface InstrumentProfileV3 {
  schema_version: 3; id: string; display_name: string;
  coordinate_frame: "icrs"; footprint: Footprint;
  footprint_semantics: FootprintSemantics;
  provenance: ProfileProvenance;
  position_angle: PositionAnglePolicy;
}
interface ExposureOffset {
  order: number; east_arcsec: number; north_arcsec: number; rotation_deg?: number;
}
interface SurveyProfileV3 {
  schema_version: 3; id: string; display_name: string; instrument_id: string;
  tiling: TilingModel; inference: InferencePolicy;
  coverage: CoveragePolicy & { target_samples_per_footprint_axis: number };
  coverage_basis_default: "single_exposure" | "effective_sequence";
  observing_sequence?: { id: string; exposures: ExposureOffset[] };
  provenance: ProfileProvenance;
}
```

Schema v3 remains strict about unknown fields. `footprint_semantics` describes
the one footprint representation in that instrument/mode profile; it is not a
bag of alternate configurations. Instrument geometry keeps the existing
`Footprint` union. `SurveyProfileV3` keeps the existing lattice/manual model and
adds only strategy sequence/basis semantics.

A v3 profile must have nonempty primary references. `parameter_sources` must
cover each physical geometry parameter and each persisted strategy-geometry parameter, including dither offsets and lattice basis/origin values. Approximate
profiles require a nonempty `approximation_notice`, assumptions and limitations.
The notice names what the approximation stands for and what it does not. These
fields are short provenance records, not a bibliography manager.

The single stored profile angle/default is `Footprint.position_angle_deg`; the PA policy does not duplicate it. Orientation validation is cross-field:

- `fixed` requires a finite profile PA and uses it; a row PA is invalid.
- `user_selected` uses one plan-level PA, prefilling from the profile angle when present. Row PA is invalid. If required and no plan/default value resolves, geometry use and export are invalid.
- `per_pointing` uses an explicit row PA, otherwise the profile angle. If required and neither resolves, geometry use and export are invalid. If not required and absent, retain the declared local east/north orientation without claiming a facility PA.
- `not_applicable` accepts no profile or row PA and exports none. Use only for rotationally invariant geometry or an approximation that explicitly omits orientation.

V3 values are astronomical degrees east of north on the ICRS tangent plane,
normalized to `[0, 360)`. Positive rotation moves the footprint's north
axis toward east. Existing v2 angle validation and normalization behavior remain
unchanged.

### 4.2 Instrument-only lifecycle

Instrument profiles remain independent registry objects. A v3 profile file may contain one v3 instrument, one v3 survey, or a matching v3 instrument/survey pair. A survey-only file must reference an already registered instrument; that registry entry may be v2 or v3, but a referenced v2 instrument retains legacy semantics and is ineligible for role-aware metrics until explicitly classified in v3. A v3 pair is validated and registered atomically. A document with neither member, mismatched IDs, or a mixed-version pair is invalid. V2 documents retain the existing required v2 pair shape.

Instrument-only source assignment and rendering use the selected instrument
profile. Selecting an instrument-only profile for output enables manual or
imported centers and generic Jasytata ICRS coordinate export. This session-only
manual output context is not a survey profile: automatic region tiling, local
lattice inference, survey overlap, coverage-completion percentages and named
survey constants are unavailable until an actual survey strategy is selected.
No fake survey is registered or exported. A role-appropriate source display is
still allowed; quantitative observed-area metrics require an eligible role and
a validated sampling policy.

Import/export is by the profile object being edited: one instrument file, one
survey strategy file, or a matching pair. The browser must not require an
instrument-only KCWI/MUSE profile to be paired with an invented survey just to
save or assign it.

### 4.3 Provenance and fidelity

Every selected v3 profile records:

- Canonical primary references (`URL` or DOI plus optional title/section).
- Parameter-level provenance for physical footprint dimensions/vertices and
  observing-sequence offsets. Derived values say how they were derived.
- Assumptions and known limitations as durable string lists.
- A footprint role and one of two fidelity values: `exact` or `approximate`.
- A nonempty approximation notice when the geometry is approximate or its role
  is an envelope/access region.

`exact` means the modeled boundary is supported at the stated instrument mode
and precision for the declared role. If its role is `observed_area`, it is the
modeled one-exposure science-active area; this never promises depth,
throughput, calibration, target completeness or an exact spherical area.
If its role is `nominal_envelope` or `target_access`, `exact` can only mean the
cited nominal envelope itself is represented exactly; it still does not become
observed area.

`approximate` means the declared role is represented with an explicit geometric
simplification. It may support approximate observed-area metrics only when its
role is `observed_area`; outputs must say “approximate.” For `nominal_envelope`
and `target_access`, area overlap is separately labeled as an envelope
diagnostic and is never described as observed science area.

The old free-form `description` remains useful for a short human summary; it is
not a substitute for the v3 evidence fields.

### 4.4 Footprint role and coverage behavior

Role is a property of the footprint representation in one instrument/mode
profile, exposed as `footprint_semantics.role`:

| Role | Meaning | Allowed metric behavior |
| --- | --- | --- |
| `observed_area` | The modeled region is the science-active area for one exposure (exactly or explicitly approximately). | It may contribute to an observed-area union. Label approximate models as approximate. A multi-exposure metric unions the modeled active regions for its selected sequence. |
| `nominal_envelope` | A nominal optical/IFU/bundle outline used for pointing or mosaic layout; it may include gaps, unilluminated edges or unmodeled fibre holes. | It may produce a separately labeled `nominal envelope overlap` diagnostic. It is excluded from observed-area union, observed-area denominators and “complete observations” claims. |
| `target_access` | A nominal field/patrol envelope in which targets may be considered for access. It is not a fibre assignment. | It never contributes area to observed-area coverage. A separate “potential targets inside nominal access envelope” count may be shown; it does not mean a target is patrol-reachable, assigned or observed. |

The 4MOST/PFS profiles use `target_access`. Their hexagons must never enter a
contiguous spectroscopic coverage union. No fibre allocation is implemented.
CALIFA, MaNGA, LVM, Hector and SAMI bundle outlines in this release are
`nominal_envelope`; an envelope dither union remains an envelope diagnostic.
Camera/IFU envelopes selected as approximate planning aids are also excluded
from observed-area metrics. KCWI slicer rectangles are `observed_area` at the
selected standard mode/PA. T80 retains its frozen v2 geometric coverage
semantics without a new v3 role field.

Metrics and map legends must name the role, fidelity and sequence basis. Do not
combine envelope/access diagnostics numerically with observed-area coverage.
The planner may optimize `nominal_envelope` only when the requested metric is
explicitly an envelope metric. `target_access` does not support Complete or
Efficient area planning.

### 4.5 Instrument modes/configurations

There is no generic nested configuration framework in v0.4.0. Use one stable
instrument profile per fixed geometry/mode. KCWI has three IDs; MaNGA has five
bundle-size IDs; MUSE has WFM and NFM IDs; MegaCam's 40-readout configuration
has a distinct ID. A change of mode or geometry receives a new ID. No profile
family is required to make these objects usable.

A named survey strategy references exactly one instrument mode in v0.4.0.
Different MaNGA bundle sizes therefore receive separate strategy IDs where each
uses the same MaNGA three-position sequence. Instrument-only profiles have no
strategy or survey defaults. Full Hector/SAMI plate reconfiguration is not a
profile mode in this release.

### 4.6 PA and orientation resolution

All stored absolute and relative angles use the astronomical convention: degrees
east of north on the ICRS tangent plane; 0° is north and 90° is east. Footprint
PA, camera PA and lattice basis orientation remain independent quantities.
`Footprint.position_angle_deg` is the single profile angle/default;
the PA policy does not duplicate it.

Resolve PA according to the declared mode:

- `fixed`: use the profile PA. A conflicting row PA is invalid.
- `user_selected`: use the one plan-level PA, prefilling it from the
  profile value when present. A row PA is invalid. If required and no plan/default
  value resolves, geometry use and export are invalid.
- `per_pointing`: use an explicit row PA, otherwise the profile value.
  If required and neither resolves, geometry use and export are invalid. If not
  required and absent, retain the declared local east/north footprint
  orientation without claiming a facility PA.
- `not_applicable`: accept no profile or row PA and export none. Use
  only for rotationally invariant geometry or an approximation that explicitly
  omits orientation.

KCWI small/medium/large use `fixed` at 0° with slices north per the
bundled planning convention; this is not an automatic Keck
`ROTPOSN`/`SKYPA` conversion. SITELLE uses `fixed`
at 0° north-up/east-left within the cited calibration limit. MUSE WFM/NFM,
PFS and 4MOST use `per_pointing` with required externally supplied
ICRS sky PA and no profile default; do not translate ESO/Subaru/VISTA rotator
keywords. `not_applicable` is selected for CALIFA PPAK, MaNGA bundles,
LVM, the selected Hector/SAMI individual bundles, Rubin, DECam and HSC because
their circular envelopes are rotationally invariant. CALIFA PPAK, MaNGA,
LVM, OmegaCAM and MegaCam use a canonical local orientation only for their
selected approximate polygon/square envelope display and overlap geometry;
their physical camera or bundle orientation is explicitly omitted and no sky PA
is accepted or exported. Orientation-sensitive envelope overlap for these
profiles remains approximate. T80 retains its existing v2 PA behavior. The `user_selected` mode is defined as one plan-level angle
(prefilled by an optional profile default, with row overrides invalid), but no
selected v0.4 profile uses it. Fixed profiles require a stored PA; profiles
using `not_applicable` accept none. The `required` flag is
false for `not_applicable` and true for fixed selected profiles.

A lattice basis rotates or spaces pointing centers only. It never supplies a
camera PA. Conversely, camera PA never rotates or infers the lattice. Exposure
offset vectors remain east/north sky offsets and are not rotated by camera PA;
an exposure footprint is rotated by resolved pointing PA plus its relative
sequence rotation. Normalize the result to `[0, 360)`.

If selected geometry or export policy requires PA, every exported pointing and
exposure row contains its resolved absolute PA. Missing PA is an error; there is
no silent zero or lattice-derived fallback. Generic center CSV remains Jasytata
coordinate output, not an observatory command file.

### 4.7 Pointing, exposure and dither semantics

A Jasytata **pointing** is one instrument-mode placement with one ICRS center,
one resolved absolute camera PA when required, one placement-provenance record,
and at most one selected observing strategy. It is not a detector, an exposure,
a visit or a plate.

Instrument geometry owns footprint, mode identity, role/fidelity and PA policy.
A survey/observing strategy owns tiling/inference/export policy and may own one
ordered default exposure-offset sequence. A pointing owns center, instrument
mode, resolved PA and selected strategy. A modeled exposure owns its 1-based
sequence order, local east/north offset and relative rotation. It represents one
distinct nominal on-sky placement; raw subframes at the same position, exposure
duration, S/N, airmass, weather, schedule and facility commands are outside the
model.

A sequence is an ordered local offset/rotation list attached to a selected
strategy and used by its pointings. With no sequence, one pointing has one
exposure at `(0, 0)` and no relative rotation. Offsets use local
tangent-plane east/north arcseconds; sequence rotations use degrees east of
north, relative to the resolved pointing PA. Convert 1 arcsec to `1/3600`
degree for geometry. Apply the same Jasytata tangent-plane-to-ICRS transform to
each offset center, independent of footprint PA. The relative rotation changes
the exposure footprint orientation only: add it to the resolved pointing PA
and normalize the result to `[0, 360)`. The selected CALIFA, MaNGA and SAMI profiles use zero
relative camera rotation; SAMI's circular-envelope rotation is immaterial. Do not
reinterpret these offsets as lattice spacing, survey overlap or adjacent field
centers.

The selected named sequences are:

- CALIFA PPAK: the ordered nominal positions `(0, 0)`,
  `(-5.22, -4.53)` and `(-5.22, +4.53)` arcsec. The source
  gives the two values as sky offsets in arcseconds from the nominal galaxy
  position; the profile records the first component as east and second as north.
  Individual measured offsets can differ. This models the three distinct dither
  positions, not the V1200 subframes taken at a position. See
  [Sánchez et al. 2016, DR3, §3](https://openaccess.inaf.it/server/api/core/bitstreams/98310fc7-1b84-48e5-81c1-0010f6c9c85a/content).
- MaNGA: the named N-S-E sequence has side `a = 1.44″`. With `C`
  as the triangle centroid and local coordinates `(east, north)`, use
  `N = (-a/(2√3), +a/2)`,
  `S = (-a/(2√3), -a/2)`, and
  `E = (+a/√3, 0)`, in that order. This places the equilateral
  triangle in the sourced north/south/east orientation; no rotator keyword
  conversion is implied. One three-exposure set is the minimum strategy unit.
  Repeated sets require explicit additional ordered entries; no repeat-count
  calculator is included. See
  [Law et al. 2015, Fig. 6 and §3.4](https://research-repository.st-andrews.ac.uk/bitstream/10023/6906/1/law2015aj19.pdf).
- SAMI DR1: central exposure at `(0, 0)`, followed by six positions at
  radius `0.7″` in 60° increments. The published source defines a
  central-plus-six radial pattern, not its absolute first angle/order. Jasytata's
  canonical geometry order starts north at PA 0° and proceeds eastward by 60°;
  this is a coordinate normalization for envelope planning, not the executed
  observatory order. The SAMI bundle envelope is circular, so this arbitrary
  phase does not change its geometric union. The positions remain nominal
  guide-camera offsets; atmospheric refraction changes the realized offsets.
  See [SAMI DR1, observing strategy](https://sami-survey.org/system/files/papers/545/sami_dr1_6.pdf).
- LVM regional sequences, MUSE recommendations and wide-field imaging dithers
  are not bundled as universal strategies. They can only be represented later
  as a sourced strategy for a named program. User-entered sequences are outside
  the selected v0.4 profile contract.

A `visit` abstraction is not required. One pointing with one ordered
sequence covers the selected CALIFA/MaNGA/SAMI cases. There is no temporal
identity, night grouping, scheduler, repeat calculator or cross-visit
completeness in v0.4.0. Multiple independent pointings remain separate
pointings.

Coverage can request `single_exposure` or `effective_sequence`.
The default is stored on a selected v3 survey strategy and always appears in the
result label; when no sequence exists the only valid basis is
`single_exposure`. Effective coverage is the geometric union of the
modeled exposure footprints for one pointing, counted once where exposures
overlap. It is not mean area, depth, throughput, exposure completeness,
reconstructed cube fidelity or S/N. For an envelope profile the result is
explicitly an effective **envelope** union; for `target_access` there
is no area-coverage result. Single-exposure coverage remains separately
requestable for every sequenced strategy.

A v3 coordinate CSV emits one row for each modeled exposure, in pointing order
and then sequence order (one row per pointing when no sequence is selected).
The stable exposure identity is the strategy ID plus its 1-based sequence
order (or the pointing ID with order 1 when there is no sequence). Each row
includes pointing/exposure identity and order, the transformed ICRS center,
instrument/mode ID, strategy ID when present, placement origin, and resolved
absolute PA when required. An authoritative imported center includes
its declared source reference. This is a coordinate list only; no duration,
raw subframe, visit, plate, fibre assignment or scheduling field is inferred.
Legacy v2 CSV field sets and deterministic ordering remain unchanged.

### 4.8 Placement provenance

The current `GenerationMethod` remains a record of how a proposal was
made; `InferenceRole` remains a switch for whether a source catalogue
may inform inference. Neither records the authority of imported center
coordinates. V0.4 adds a placement-origin value; repeated labels such as
`manual` or `local_inference` describe the origin's meaning,
not the algorithm implementation already recorded by `GenerationMethod`.

Every planned/source pointing can distinguish:

- `manual`: center entered or clicked by the user;
- `imported_unverified`: user-supplied center file with no declared
  authoritative survey source;
- `authoritative_import`: centers the user declares from a named
  survey/release/product, with a source reference;
- `declared_profile_lattice`: candidate centers generated from the
  survey's persisted `TilingModel` basis/origin;
- `local_inference`: candidate centers from an inferred local grid.
  The fit and its anchor provenance remain diagnostics, not a newly declared
  survey lattice.

Store origin on each planned/source pointing and retain it with the
session/catalogue record; `authoritative_import` also stores the source
reference. This is a user-declared origin, not independently verified by
Jasytata. Filename or visual grid regularity is not evidence. The v2
`TilingModel` already persists a declared lattice, so do not duplicate
its basis/origin in every row. Do not add placement history to instrument
geometry. Every v3 coordinate export includes placement origin, instrument/mode
ID, strategy ID when present, and source reference for authoritative imports.
Legacy v2 exports keep their existing fields.

### 4.9 Mixed-scale coverage sampling correctness

Coverage correctness is defined over all eligible, resolved geometry in the
selected metric, including mixed input instruments. In role-aware observed-area
metrics, only v3 `observed_area` footprints contribute. A positive-area
intersection must not disappear because the active output instrument is much
larger. Resolution is based on the smallest relevant footprint scale in the
selected coverage set, not the largest footprint, the active survey alone, a
mean or an average.

For each footprint, define characteristic scale in local tangent-plane degrees:
circle diameter; rectangle's shorter side; polygon's minimum width (minimum
distance between parallel support lines); and, for a compound union, the
smallest scale of any nonzero-area child. Let `s_min` be the smallest
scale among all contributing footprints, and `N` be
`target_samples_per_footprint_axis`, a required v3 coverage-policy
value with `N >= 8`. A v2 active survey that enters a mixed-scale run uses a
v0.4 run-level default `N = 8`; the user may raise it but not lower it. An
instrument-only manual run also defaults to `N = 8`. No new field is written
into a v2 profile. The effective local cell pitch must be no coarser than
`s_min / N`. A deterministic adaptive/multiscale estimator may
refine only where small geometry contributes, but it must meet this same
per-footprint resolution rule and union semantics. The rule also applies to a
separately requested nominal-envelope metric.

`max_samples` is a hard work/memory budget, not permission to coarsen
silently past the correctness pitch. If the bounded deterministic estimator
cannot meet that pitch, return an explicit under-resolved result with no
authoritative coverage fraction and do not use it to claim Complete/Efficient
coverage. The UI must show the under-resolved state and offer a higher-budget or
instrument-scoped re-run. Do not convert a zero-sampled small field into zero
physical coverage.

The permitted numerical approximation is binary cell/leaf classification at
the reported effective pitch. For a resolved run, the absolute area error is
bounded by the summed area of cells/leaves intersecting a modeled footprint or
selected-region boundary, plus the separately declared geometry/projection
approximation. Expose the pitch and boundary-cell area upper bound (or its
fraction of the selected region), and do not report greater precision than
those bounds support. Results must be deterministic for the
same ordered profile/tile/polygon inputs and stable under unrelated registry
insertion order.

The pure frozen S-PLUS v2 path retains its existing sampling and metric
semantics. A mixed-scale run that includes v3 geometry uses the v0.4 sampler
and reports pitch/budget status. V3 `nominal_envelope` and
`target_access` records are excluded from observed-area metrics. V2
records keep `legacy_v2` semantics and are never auto-classified as
exact/approximate or assigned a v3 role. A separately labeled legacy-compatible
metric may retain existing v2 union behavior while including v3
`observed_area` records; it must not include v3 envelope/access
geometry. In that mixed metric, all included geometry, including v2 records,
participates in `s_min` resolution. Pure T80/S-PLUS guarantees remain
unchanged; mixed-scale work cannot claim more precision than reported sampling
supports.

## 5. Schema-version and migration decision

**Decision: retain Schema v2 for the frozen S-PLUS profile and existing v2 imports; use Schema v3 for accepted v0.4 semantic fields or the instrument-only document structure.** V3 is not an automatic release-version bump. It is required because strict v2 validators reject unknown keys and v2 documents require an instrument/survey pair.

Compatibility behavior:

- A v0.4 reader accepts v2 profile pairs unchanged and labels their geometry
  `legacy_v2`. It does not infer `observed_area`,
  `nominal_envelope`, `target_access` or exact/approximate
  fidelity. Their historical union behavior is available only in a separately
  labeled legacy-compatible metric, never labeled observed-area coverage. A
  known patrol/access profile is excluded from every observed-area metric.
  Role-aware metrics require explicit v3 classification. The frozen built-in
  S-PLUS workflow retains its historical output and coverage.
- A v0.3 reader accepts pure v2 exports exactly as before and rejects v3 members.
  V0.4 never strips v3 role, fidelity, provenance, PA or sequence fields to
  create an apparent v2 document.
- V0.4 export intentionally keeps a complete instrument/survey pair as v2 when
  it has no v3 fields or semantics, preserving v0.3 readability. A standalone
  profile document or profile carrying accepted v0.4 semantics is v3.
- V2 to v0.4 import is a lossless read, not a migration. No automatic migration
  occurs. An explicit edit may structurally lift geometry/policy fields to v3
  without changing their values; assigning roles, fidelity, provenance or PA
  semantics is a semantic migration and requires user confirmation wherever
  v2 cannot supply the value.
- The protected canonical S-PLUS v2 document keeps the same member names,
  values, field set and deterministic sorted-key serialization. Existing
  generated S-PLUS exports remain byte-compatible. Arbitrary input whitespace
  and key order were not preserved before and are not promised; accepted v2
  documents remain semantically compatible.

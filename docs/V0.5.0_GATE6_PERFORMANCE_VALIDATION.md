## Measurement method

Canonical command, from `frontend/`:

```sh
npm run benchmark:baseline
```

The original eleven Gate 0 workloads remain intact. The same harness adds
rotated/offset mixed-shape masks, isolated shared selection, dense MUSE,
high-DEC KCWI, RA-wrap DECam, and registered SAMI effective-sequence planning,
with both Complete and Efficient. Production planning keeps the 1,200 search-site
guard. Only the inherited pure-enumerator stress fixture uses its explicit
5,000-site budget. No candidates, samples, geometry fidelity or precision are
removed to improve timings.

Environment: Linux x86_64, AMD Ryzen 7 5800X (8 cores / 16 threads), Node
`v22.22.3`, npm `12.0.2`, Vitest `2.1.9`, installed Aladin Lite `3.8.2`.
Measurements use Vitest's `performance.now()` distributions, 100 ms warmup,
250 ms target measurement time and its minimum ten observations for slow
operations. Times are means in milliseconds, observational, with no timing
assertions or CI thresholds. Small differences in unchanged paths are noise.
The table measures synchronous core work; it does not include browser Worker
startup, paint, event-loop latency or a subjective responsiveness assessment.

Before measurements were recorded before scientific edits. A Node Inspector
CPU profile sampled 30 repetitions of each additional Complete project plan
and 30 isolated compound-mask selections. Its self-time samples were:
`greedyChoose` 46.0%, `weightSum` 18.5%, compound `integrate` 16.8%,
`signedClearance` 8.9%, `containsShape` 2.1%, GC 1.3%, angle normalization
1.1%, and `tileMask` 0.7%. These percentages describe this explicit profiling
mix, not every project. End-to-end and isolated mask timings identify costs
that the mixed CPU profile can underrepresent.

## Optimizations and numerical safeguards

1. **Redundant selector work:** prepare each candidate's immutable in-region
   weight, outside area and ascending nonzero-mask indices once. Gain and
   overlap are accumulated separately in ascending sample order; overlap is
   never calculated by subtracting rounded sums. The current remaining-array
   index still breaks exact ties. Complete/Efficient use the same single
   production `greedyChoose`; stopping comparisons are unchanged.
2. **Immutable preparation:** one mask-builder closure per candidate or coverage
   operation reuses structurally identical containment testers and local bounds.
   No scientific cache is shared between planning runs. Compound area
   integration prepares primitive inverse rotations once and removes repeated
   map/spread allocation, retaining depth 12, leaf predicates, quadrant order
   and arithmetic reduction order.
3. **Conservative sample rejection:** skip containment outside enclosing local
   bounds, with the existing shape tolerances and an arithmetic margin. Polygon
   cross/dot tolerances have an angular reach dependent on edge length; the
   padding accounts for that, and degenerate edges disable sample pruning.
   The inherited whole-grid rejection is unchanged. Every allocated sample and
   weight is retained; full-scan reference tests protect boundary behavior.
4. **Operation-scoped sequence area memoization:** key the exact resolved union
   shape, offsets, component order and PA, after the frozen sky round trip.
   Near-equal offsets are never rounded or treated as equal. This safely reuses
   identical unions without replacing Gate 5 exposure mathematics. Slightly
   different sky round trips still require separate integrations.
5. **Rendering and React:** Aladin's installed `add(shape, false)` suppresses
   per-symbol redraw requests; `reportChange()` requests one repaint for the
   candidate layer, including clearing/hiding. Existing viewport culling, symbols,
   1,200-per-source display limit and full scientific candidate arrays remain.
   Hidden layers skip candidate filtering. App memoizes accepted/pending exposure
   counts to avoid registry lookup/cloning on unrelated visual rerenders.

## Worker, cancellation and result publication

After synchronous optimization, SAMI effective-sequence plans still require
roughly 0.69 seconds of core work; the dense MUSE case requires about 0.07
seconds. These measured tasks justify moving canonical App planning and coverage
operations off the main thread. Merely deferring a whole synchronous call would
leave those uninterrupted computations on the browser thread. Cooperative
chunking would require resumable changes across masks, greedy rounds and the
recursive union integrator; a dedicated Worker reuses the deterministic core
without introducing a second scientific algorithm.

A local module Worker receives a structured-clone-safe request with ICRS inputs,
placement, real profile/strategy references, canonical PA/sequence choices and
validated session profile snapshots. `executePlanningOperation` has no React,
DOM, Aladin or scheduling dependency. The Worker reconstructs an isolated
registry, executes the same planner/coverage functions, and returns one complete
result or a typed scientific refusal. Imported profiles are supported. No
backend, partial-plan messages or progress percentage are introduced.

There is one dedicated Worker per operation, terminated on completion, failure
or cancellation. AbortController handles explicit **Cancel planning**, input
invalidation and coverage-effect cleanup. App checks both the input revision
and current run controller before publishing results; older runs cannot clear
a newer busy state. Cancellation leaves region, project placement and user
inputs intact. Transport handlers cannot settle an already-cancelled request.

**Chunking is not used:** there is no chunk size or parallel reduction, and no
chunk-size parity claim is needed. Worker cancellation is by termination, not
by publishing a partially selected plan. When Workers are unavailable, the same
operation executes synchronously. Arbitrary custom geometry callbacks also
retain the synchronous API; canonical transport eligibility verifies callback
identity and unchanged choices so it cannot silently discard an override.

## Role/fidelity, mixed-scale sampling, and under-resolution

The release matrix exercises every production profile under its declared role.
Exact KCWI observed-area geometry can yield an authoritative resolved
observed-area fraction. Approximate envelopes retain envelope terminology and
non-authoritative fidelity even when a fraction is computable. PFS and 4MOST
target-access profiles never enter observed-area contributors; the UI explicitly
says target access is not observed coverage and does not claim fibre
assignment/completeness. T80 stays on its historical Schema v2 coverage path
without a fabricated v3 role or fidelity.

The Gate 6B mixed-scale invariant is rerun with the independently specified
large 1.4° rectangle and small observed-area KCWI profile. The large-only pitch
is 0.175°; adding KCWI changes the required pitch to 0.000291666667° and the
fixture resolves 29,584 samples. This demonstrates that the smallest
contributing observed geometry controls the grid and a large footprint cannot
hide it. Repeating with a tiny PFS target-access profile leaves the observed
grid at the large-only scale; target access is filtered before observed-area
sampling. The fixture's resolved observed fraction is 0.10425.

The hard-budget regression keeps `max_samples=1000`: the same observed mixture
requires 29,584 samples and returns `under_resolved` with 992 sampled cells.
Runtime result, planner refusal, and UI alert agree. Required Complete/Efficient
planning does not continue scientifically; no authoritative percentage,
remaining fraction, 0%, 100%, NaN, or completion claim is rendered. UI explains
required resolution and the configured budget. The budget was not raised.

behavior was therefore exercised with the real React application in Vitest
jsdom, real registry/science/export code, and a deterministic Aladin boundary
adapter. No live-browser screenshot or visual manual pass is claimed.

New-project workflows start without a catalogue and cover exact observed-area
KCWI, approximate nominal-envelope LVM, and target-access PFS. They select the
instrument, require PFS PA, stage a sky center, preview and accept one pointing,
inspect role/fidelity metadata, and export generic ICRS center CSV. The exports
contain no survey, epoch, sequence, fake physical PA, or target-assignment
claim.

The existing-project path loads the reference S-PLUS catalogue, retains T80
association, selects a region, generates and reviews a real proposal, accepts,
checks coverage and exports in historical order. Regression tests verify source
rows remain unchanged. Separate mixed-catalogue tests assign source instruments
independently, render each assigned geometry, retain inference-role semantics,
apply the output strategy only to proposals, filter observed coverage by role,

compatibility; v3 instrument-only import/register/activate/manual-center/profile

activation, and round trip. Malformed files and duplicate/incompatible IDs

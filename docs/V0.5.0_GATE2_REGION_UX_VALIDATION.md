# Jasytata v0.5.0 Gate 2: region authoring and reference UX

## Scope and canonical region

This gate implements region inputs and an independent visual reference marker
on branch `0.5.0`, following the frozen
[V0.5.0 Gate 1 contract](V0.5.0_GATE1_PLACEMENT_CONTRACT.md). It adds no
project lattice authoring, candidate planner, instrument integration, manifest,
Worker, or planner optimization. The v0.4.0 planner and coverage mathematics,
constants, fixtures, PA, sequence, and export policies remain unchanged.

`frontend/src/science/regions.ts` provides pure constructors:

```ts
rectangleRegionFromCenterSize({ center, width, height, unit }): SkyPolygon
rectangleRegionFromCorners(corner1, corner2): SkyPolygon
```

Coordinates are canonical ICRS `{ ra_deg, dec_deg }` in degrees. Units are
`deg`, `arcmin`, and `arcsec`, normalized to degrees internally. Output is only
the existing `SkyPolygon` with implicit closure. Planner and coverage never
receive an authoring discriminator or rectangle-specific region type.
Polygon drawing retains the existing native Aladin selector and
`skyPolygonFromVertices`; completion and both rectangle constructors all enter
`App.applySelectedRegion` and the existing `validatePolygon` contract.

## Rectangle semantics and branch

Rectangles are axis aligned in Jasytata's frozen local east/north approximation:

```text
east  = wrapped_delta_RA * max(cos(center DEC), 0.01)
north = DEC - center DEC
```

Width is the **full east-west angular extent at the declared center**, not raw
RA extent. Height is the full north-south angular extent. The half offsets are
`width_deg / 2` and `height_deg / 2`. Conversion uses the existing
`localOffsetToSky`; implied corner widths use `skyToLocalOffset`. Region
orientation is independent of instrument PA and lattice rotation. No rotation
input is implemented.

The deterministic order is **south-west, south-east, north-east, north-west**
on the continuous unwrapped RA branch. Stored RA is normalized to `[0, 360)`;
there is no repeated closing vertex. Tiny modulo rounding at zero is
canonicalized without altering the shared scientific transform.

Opposite corners use the shortest signed RA difference in `[-180, 180)`.
Center RA is the midpoint of that continuous branch, normalized to `[0, 360)`;
center DEC is the arithmetic midpoint. Height is absolute DEC separation and
width is absolute east separation at that same center. Thus `359.9°` and
`0.1°` form a narrow `0.2°` RA rectangle in either input order. Equivalence
regressions compare corresponding vertices within the frozen `1e-10°`
tolerance at mid latitudes, RA zero, high positive/negative DEC, and both
cosine-clamp polar fixtures.

Rectangles refuse RA extent **at or above 180°** before normalization. At
exactly 180° the shortest branch is ambiguous and the polygon's wrapped edge
cannot reliably express the user's intended rectangle; an actionable error
requests a smaller region. This authoring restriction does not change the
existing polygon acceptance rule (span at most 180°). Centers and vertices
must be finite, RA canonical, DEC strictly within `(-90, 90)`; pole-reaching
rectangles are refused. Width/height must be finite and positive. Existing
polygon duplicate tolerance (`1e-6°`) and effective area threshold
(`1e-5 deg²` using the existing validator) apply. No requested extent is
silently clamped to another region.

## Coordinates and compact controls

`parseSkyCoordinate(ra, dec)` delegates to the existing `parseRaDegrees` and
`parseDecDegrees`. Decimal fields denote degrees. Colon sexagesimal RA denotes
hours and Dec denotes degrees; three whitespace-separated fields use the
same semantics. Existing explicitly unit-qualified formats retain their
existing parser interpretation. Examples covered:

```text
02:30:44.67    -21:10:19.5
02 30 44.67    -21 10 19.5
37.686125     -21.1720833
```

Bare two-field whitespace input is rejected in the new labelled authoring
boundary because the legacy RA parser cannot safely distinguish its intended
unit. This does not change catalogue or pasted-pointing parsing. Other invalid
input receives an inline `role=alert` message. Forms validate on explicit
submission; keystrokes and failed drafts leave the previous region, marker,
plan, and coverage untouched.

`RegionAuthoring` exposes a labelled mode selector and only the active controls.
Polygon start, finish, cancel, redraw, clear, and Escape continue to use the
existing workflow. Switching authoring mode cancels a native drawing without
applying a new region. `ReferenceCoordinate` uses a keyboard-accessible
`details` disclosure. Every input has an associated label. The existing panel
flow and responsive breakpoints are retained; no nested scroll pane was added.
Only the native drawing instruction's wrapping was corrected for narrow maps.

## Reference independence

The marker is separate App session state and a dedicated Aladin catalogue named
`Reference coordinate · visual aid`, with a large pink **plus**, a persistent
`Reference coordinate` label, and accessible status text. It has no entry in
the pointing lookup, proposed-pointing catalogue, `TileRecord`, planner inputs,
coverage inputs, or exports. Placement pans only the map view to the marker,
retaining FoV; it sets no region, pointing, PA, placement policy, or origin.
Clear removes/hides only this catalogue's source. Instrument and observing
strategy switches, region changes, and scientific context changes retain it.
New project clears it and resets both new forms' drafts using the same session
reset boundary; a placed marker counts as project content for confirmation.

## Region-change dependencies

`applySelectedRegion` validates before changing state and increments the region
revision. It clears pending proposal acceptance, candidate centers, inference
anchors, stored plan/proposal context and diagnostics, coverage result,
scientific refusal, stale debug request, and any selected pending preview tile.
It leaves catalogues, accepted/manual pointing identities, selected output
instrument/strategy, coverage strategy, PA input, imported-center draft,
reference marker, theme, and layer preferences intact. Existing accepted
pointings are user data; their coverage is recomputed for the new region with
the existing cancellation-protected coverage effect.

Polygon redraw retains the previous behavior of removing the old selection
before drawing. Clear selection uses the same invalidation boundary. Plan and
explicit measurement results/errors are revision guarded, so a delayed request
for a cleared region cannot restore its preview or diagnostic. Output context
switches now preserve the independently selected polygon while invalidating
context-dependent derived values, as specified in Gate 1.

## Native wheel policy

Inspection of the installed **Aladin Lite 3.8.2** distribution found that
`catalogCanvas` registers a native wheel listener through `Utils.on`, calls
`preventDefault()` and `stopPropagation()`, then accumulates `zoomDelta` for
animated zoom. Merely overriding a React bubbling handler or using Aladin's
`wheelTriggered` callback would not recover default page scrolling.

`installMapWheelPolicy` attaches a **passive native capture** wheel listener to
the map container before Aladin initializes:

- Plain wheel/touchpad gestures stop propagation before Aladin's canvas
  listener and retain browser default scrolling. No manual scroll replay is
  used.
- Ctrl or Meta/Command wheel passes through to Aladin's native zoom listener.
- No document/window wheel interception, synthetic React policy, or passive
  `preventDefault` is used; cleanup removes the listener on unmount.
- Persistent hint: `Ctrl / ⌘ + wheel to zoom · drag to pan`.
- Native zoom buttons are explicitly enabled (`showZoomControl: true`). Clicks,
  polygon selection, and pan event paths are unaffected by this wheel listener.

The existing desktop shell uses scrollable side panels; the responsive layout
permits document scrolling. The policy preserves available browser scrolling,
without creating a new scroll region or changing layout ownership.

## Inherited scientific limits

The local transform and `0.01` cosine floor are a frozen approximation, not a
spherical or gnomonic rectangle. High-DEC numerical equivalence does not prove
physical accuracy near a pole or across broad fields. Exact poles and ambiguous
rectangle RA spans are refused. The existing planner can additionally refuse
footprint-expanded branches, sampling resolution, or candidate budgets even
when a selected polygon is valid. No planner thresholds or T80 compatibility
behavior have been changed to accept rectangles.

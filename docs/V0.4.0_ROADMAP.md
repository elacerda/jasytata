# Jasytata v0.4.0 development roadmap

## Authority and baseline

This is the current development gate authority. The
[v0.3.0 roadmap](legacy/V0.3.0_ROADMAP.md) remains historical evidence, not an
instruction to reopen its gates. The original published v0.3.0 snapshot is
`2b4e5d23bbc42d04b1155a4f7733575d58810b44`; it is historical release evidence.
The corrected v0.3.x baseline from `main`
(`f66dfe4a2868cc7222e31b17b4c979390265ae34`) was integrated into branch `0.4.0`
by merge `e7896b4cc3b3c6d6fe8ca19cb3eefdf729e4c6cd` after Gate 3 and before
Gate 4. This integrated state is the current v0.4.0 development baseline.
Gate 2 originally started from the verified Gate 0–1 HEAD
`19b4995d8d82599bd2f199229ddae29441b4695d`. The corrected v0.3.x scientific
behavior is regression-protected, including the intended T80/S-PLUS compatibility
contract. Changes to that behavior require explicit authorization and independent
scientific evidence.

The scientific sequence is:

```text
real instrument library
  -> empirical requirements
  -> profile contract derived from those requirements
  -> scientifically validated rectangle / circle / hexagon footprints
  -> placement lattice independent of footprint shape
  -> PA / rotation / dithering
  -> final validated instrument profiles
```

Schema v2 already supplies rectangles, circles, simple polygons, compound unions,
footprint PA, and placement by two independent east/north basis vectors. It also
separates instrument geometry from survey policy. Reuse these capabilities.
There is no presumed schema v3, new generic footprint engine, or `HEX_GRID_V1`.
A hexagon can already be a polygon; a triangular lattice already uses ordinary
basis vectors. Any contract change must cite an empirical requirement in the
[instrument matrix](V0.4.0_INSTRUMENT_MATRIX.md), explain the existing capability
it exceeds, and receive acceptance in its designated gate.

## Fidelity and release scope

Every instrument **selected for the release library** must have a scientifically
correct, documented, usable profile. The studied candidates are not automatically
the final release selection. Gate 2 freezes the intended planning semantics and
selection; Gate 6 accounts for every selected case and mode.

Instruments need not share the same geometric or operational sophistication.
Detailed CCD masks, exact chip gaps, complex focal-plane mosaics, fibre patrol
regions, and sparse multi-IFU geometry are **not automatic release blockers**.
They may be deferred when they refine an already meaningful planning profile.
They become requirements when their omission would change the stated planning
semantics. A patrol region must never be counted as observed spectroscopic area.

An approximation is acceptable only when it preserves the intended planning
semantics, records assumptions and provenance, states limitations explicitly,
and makes no higher-fidelity claim. Never substitute a materially inappropriate
rectangle merely to claim support. An envelope approximation must be labeled as
such, with no promise of gap-free, exposure-complete or target-complete coverage.

file or output-policy workflow is recorded for Gate 2, not repaired by a fake
survey in Gate 1.

## Validation and working discipline

Use `AGENTS.md` and code-review-graph: minimal context first, symbol/relationship
navigation, impact radius before existing-code changes, then change/review context
before final validation; update stale graphs. Exact source, tests and scientific
documentation outrank graph summaries. Follow the repository documentation style.

Develop with focused profile/registry tests. Gate 1 acceptance requires:

```sh
make test
make lint
make typecheck
make build
git diff --check
```

No scientific fixture expectations, constants, coordinate/coverage semantics or
T80 policies may be edited to accommodate a new profile. UI tests that assumed
one bundled instrument may track registry membership instead, while retaining
their scientific/default assertions. No ID-specific scientific branches.
Do not modify or stage local untracked `.codex/` or `poly.txt`. Leave work ready
for review; no commit, push, release, tag or deployment in this bootstrap.

## Gate 8B browser-fix verification

- [x] The app shell, workspace, and map fit the viewport with no document vertical scrollbar or reachable blank area below the app.
- [x] Side-panel wheel input scrolls the panel under the pointer without moving the document or changing the map zoom.
- [x] Catalogue instrument, inference participation, and output profile controls remain within the left column; catalogue controls are usable at 1024 px.
- [x] The catalogue status dot and its outer halo remain fully visible while the status text ellipsizes.
- [x] The `Load reference` action is absent and normal `Load catalogue` upload works.
- [x] A user-uploaded `tiles_nc.csv` works in the S-PLUS/T80-South output context without a spurious PA rendering error.

The S-PLUS/T80-South check used the normal CSV picker, assigned `t80-south`, and generated a plan for the frozen historical polygon. The 4,774-row catalogue produced a valid S-PLUS result with 60 inference anchors, 107 compatible neighbor pairs, and no PA error. It reported 99.7% existing coverage and no admissible new centers for that region.

The earlier document overflow came from the absolutely positioned `RA and DEC pairs` visually hidden label escaping `.import-section`, which had no positioned containing block. At a 757 px Chrome viewport the baseline was `innerHeight=757`, `clientHeight=757`, document `scrollHeight=1892`, and body `scrollHeight=757`; the label's bottom was at 1892 px. Making `.import-section` positioned contains that label inside the left-panel scroll area. At both tested viewports after the fix, `document.documentElement.scrollHeight` equaled `clientHeight` (900 px), and `.app-shell` was exactly 900 px tall.

The plain-wheel policy now stops unmodified wheel events at the map and does not cancel them. The document is fixed to the viewport, so there is no document scroll target. Ctrl/Meta + wheel reaches Aladin and zooms; dragging still pans. Left and right panel wheel input changed only the panel under the pointer.

At 1024 px, the left panel ended at x=225 and the map began at x=225; all left-panel selects ended at or before x=202. Catalogue instrument and inference controls use one column, and export fields stack at the narrow desktop breakpoint. The status text wrapper owns ellipsis clipping while the dot's 3 px outer halo remains unclipped. The narrow inspector also has no horizontal overflow.

PA validation remains active. The rendering error is legitimate for a tile associated with a Schema v3 instrument whose policy is `per_pointing` with `required: true` when neither the tile nor profile supplies an angle. S-PLUS/T80 uses the Schema v2 T80 instrument, which has no required per-pointing PA policy; a normal uploaded S-PLUS catalogue in that context renders without the error.

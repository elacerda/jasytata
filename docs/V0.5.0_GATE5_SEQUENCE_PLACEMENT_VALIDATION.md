# v0.5.0 Gate 5 — project placement and observing-sequence validation

Gate 5 connects the nominal project-lattice centers selected by Gate 4 to real
registered observing sequences. Placement remains the source of regional
centers; an observing strategy describes ordered exposures around those
centers. A sequence does not create a regional tiling policy, candidate center,
survey footprint placement, or project lattice.

## Runtime representation and expansion

`planRegion` returns nominal `TileRecord`s. A project-lattice result retains
its ICRS center, `user_declared` placement provenance, lattice `(i,j)`,
instrument profile ID, strategy ID, and resolved nominal PA where applicable.
Proposal review and acceptance continue to operate on those nominal rows.
Generate plan does not require the optional Preview lattice state.

`expandPointingExposures` is a generic observer-facing projection over the
existing `resolvePointingGeometries` and v0.4 `deriveExposurePlacements`
machinery. It consumes one nominal pointing, the registered strategy's
`ExposureOffsetV3[]`, and the resolved PA policy. The resulting
`ExpandedPointingExposure` contains a deterministic child ID, parent nominal
pointing ID, optional parent lattice `(i,j)`, strategy and sequence IDs, order,
source east/north offsets, relative rotation, resolved ICRS center, and resolved
PA when declared. It never replaces the parent tile or changes lattice
identity. No SAMI-, CALIFA-, or MaNGA-specific expansion branch was added.

Project candidates still pass through the shared `greedyChoose` selector used
by registered-survey candidates. When the selected coverage basis is
`effective_sequence`, existing pointing geometry and geometric-union coverage
are evaluated during candidate selection. Otherwise selection uses the
nominal single-exposure footprint. In either case the result contains nominal
pointings; accepted or selected centers are expanded for exposure counts and
observer-facing export.

## PA and offset convention

The v0.4 sequence contract in `frontend/src/science/exposure-sequence.ts` is
unchanged. East/north offsets are tangent-plane sky offsets from the nominal
center and are converted by `localOffsetToSky` independently of PA. The
sequence's relative rotation is added to the resolved nominal PA for exposure
orientation only. Project-lattice rotation changes the nominal center basis;
it is not applied to exposure offsets. An explicit follow-instrument-PA
placement rotates the lattice basis while leaving the sequence offset
transformation unchanged.

Regression tests compare an independent 17° lattice with 45° instrument PA,
then a lattice explicitly following 45° instrument PA. Both retain `(i,j)`;
their sequence centers equal the sky-local offsets from each nominal center,
and declared exposure PAs follow the existing 45° plus relative-rotation rule.

exposure expansion. Effective-sequence coverage reuses the existing v0.4

approximation. A clearly labeled synthetic profile test covers the

## Proposal and export behavior

The proposal panel shows nominal-pointing and derived-exposure counts without
presenting child exposures as lattice sites. Its sequence label is per nominal
pointing. Counts are read from the active registered strategy, not hard-coded
production logic.

Sequence-bearing strategies expose two separate downloads:

- **Nominal pointings**: one row per enabled accepted nominal center, using the
  selected strategy's existing export policy and nominal PA. Sequence offsets
  are not applied. The filename is `new_tiles_nominal_pointings.csv`.
- **Expanded exposures**: one row per enabled registered sequence element,
  ordered by accepted nominal pointing and then profile sequence order. The
  observer ID identifies the parent pointing and one-based exposure order; the
  selected strategy's existing columns and constants remain in force. The
  filename is `new_tiles_expanded_exposures.csv`.

Tests verify that nominal row count equals accepted nominal pointings, expanded
row count equals the sum of registered sequence lengths, and grouped row order
is deterministic for multiple pointings. Strategies without a sequence keep
their current `new_tiles.csv` export. The S-PLUS/T80-South golden export remains
unchanged.

## State independence and regression evidence

Sequence changes clear dependent plan and coverage results while retaining a
compatible selected region and project placement. Project-placement, region,
instrument-PA, and strategy edits invalidate their dependent nominal plan,
coverage, counts, and exports. Expanded exposures and export rows are derived
from current accepted nominal rows at use time; no independent exposure cache
was added. Reference markers and Candidate-layer visibility do not change
scientific inputs or results.

Before Gate 5 edits, the Gate 4 invariant audit passed: one production
`greedyChoose`; both candidate adapters using that selector; S-PLUS on its
registered-survey path; project `(i,j)` retained; no off-lattice synthesis;
`target_access` excluded from regional area planning; and Generate plan
independent of Preview lattice state. Its focused audit ran 96 tests across six
files. The post-change full suite also passes the Gate 4 Complete/Efficient
project tests and frozen S-PLUS response fixture.

## Validation status and limitations

Focused Gate 5, App, export, and compatibility tests pass: 154 tests across six
files. `make test` passes all 835 tests across 52 files. `make lint`,
`make typecheck`, `make build`, and `git diff --check` pass. The build reports a
Vite advisory that the minified JavaScript chunk exceeds 500 kB; no performance
optimization was done in this gate. `npm run benchmark:baseline` passes in
4.536 seconds; the timings are observational and have no pass/fail threshold.

The refreshed code-review graph analyzed 13 changed files and 42 changed
symbols, with a 0.55 risk score and eight inferred test gaps; its review context
covered 262 impacted nodes in 40 files. It marked four public/profile types as
untested and four planner/UI paths as reached only through callers. Focused
tests cover those runtime paths; the graph is a navigation aid, not a substitute
for the source contracts or test evidence.

Real browser validation for Gates 2–5 remains pending: the available
computer/browser inventory contained no apps or browsers. No browser-only
success is claimed.

The current registered sequence strategies all use `effective_sequence` and
approximate `nominal_envelope` geometry. Their regional metrics describe the
declared geometric model only; they do not establish active detector/fibre
coverage, allocation, target completeness, depth, or data-reconstruction
semantics. The single-exposure sequence path is verified with a clearly
synthetic unit fixture, not attributed to a real registered strategy. Project
manifest persistence, Workers, performance optimization, scheduling, fibre
allocation, exposure-time optimization, and release work remain deferred.
